# 中转模式：让远程 agent 控制用户的浏览器

**什么时候读这份**：用户问「能不能在服务器上／另一台机器上用」「远程控制我的
浏览器」「中转/relay 怎么配」，或 `owb daemon-status` 显示 `mode: relay`。

## 两种模式的区别

**本地模式（默认，什么都不用配）**——daemon 和浏览器在同一台机器：

```
你（agent） → owb CLI → daemon(127.0.0.1:43917) → 扩展 → 浏览器
```

**中转模式**——浏览器在用户的机器上，agent 和 daemon 在别处（服务器、另一台
电脑、云端），两端各自**拨出**到一个公网中转，按同一个 token 配对：

```
浏览器/扩展（用户机） ──wss──►┐                ┌──wss── daemon + owb CLI（agent 这边）
                            │  中转 broker   │
                            └────────────────┘
                        （Cloudflare Workers + Durable Objects）
```

关键点：**两端都是主动拨出，用户机不需要开放任何端口、不需要公网 IP**。

## 先搞清楚现在是哪个模式

```bash
owb daemon-status
```

返回里 `mode: "local"` 或 `"relay"`（relay 时还有 `relay_url`）。
用户那边看扩展弹窗：点浏览器工具栏的 OWB 图标，上半部分的拓扑图**本地模式只有
两个节点**（浏览器—daemon），**中转模式会多出中间那个"中转"节点**。

## 配置引导：怎么带用户走完

这是**用户机器上的操作 + 你这边的环境变量**，你不能全代劳。按下面的顺序，
**每一步等用户确认再走下一步**。

### 第 0 步：确认需求（别急着配）

先问清楚：浏览器在哪台机器上、agent 在哪台机器上。**如果两者其实是同一台，
不需要中转模式**，本地模式更快也更安全，直接跳过这整份文档。

### 第 1 步：有没有中转地址

- **已经有了**（用户之前部署过）：拿到那个 `wss://…` 地址，跳到第 2 步。
- **还没有**：需要用户用自己的 Cloudflare 账号部署一个（免费额度够用）。
  仓库里 `owb-relay/README.md` 是完整部署文档，核心就三条：

  ```bash
  cd owb-relay && npm install
  npx wrangler login       # 浏览器里授权一次
  npx wrangler deploy      # 输出 https://owb-relay2.<你的子域>.workers.dev
  ```

  ⚠️ **必须用用户自己的 Cloudflare 账号部署**，理由见下面「安全边界」。
  部署完把输出里的地址改成 `wss://` 开头就是中转 URL。

### 第 2 步：生成 token

token 是**远程控制这个浏览器的唯一钥匙**，32 字节随机足够。两个生成方式：

- 扩展弹窗「中转」页上有「生成」按钮（推荐，用户自己点，你看不到值）
- 命令行：`node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`

⚠️ **你不需要知道 token 的值**。让用户自己生成、自己填两端。**不要把 token
回显在对话里、不要写进仓库文件、不要落进日志**。真需要引用时用扩展弹窗显示的
掩码形式（`abc123…wxyz`）确认两端一致就够了。

### 第 3 步：配扩展端（用户在自己机器上操作）

告诉用户按这个顺序点：

1. 点浏览器工具栏的 OWB 扩展图标
2. 切到下半部分的 **「中转」** 标签页
3. **中转 URL** 填第 1 步那个 `wss://…` 地址（必须 `wss://` 开头，否则保存时会报错）
4. **中转 TOKEN** 填第 2 步的 token（或直接点「生成」再「复制」）
5. 点 **保存**

保存即写入扩展存储并立刻重连，不用重启浏览器。此时状态会停在
**「配对中…」**，提示「等待 daemon 用同一 Token 接入中转」——**这是正常的**，
另一端还没上线。

### 第 4 步：配 daemon 端（你这边）

daemon 靠两个环境变量启用中转，**两个都齐才生效**：

```bash
export OWB_RELAY_URL="wss://owb-relay2.你的子域.workers.dev"
export OWB_RELAY_TOKEN="<跟扩展端完全一致的 token>"
```

⚠️ **daemon 只在启动时读环境变量**。如果已经有一个本地模式的 daemon 在跑，
光设环境变量没用——**必须先把它停掉**，再让下一条 `owb` 命令重新把它拉起来
（CLI 会用当前进程的环境变量 spawn 新 daemon）。

⚠️ token 别写进仓库里的文件。用 shell 环境变量，或用户自己的密钥管理。

### 第 5 步：验证

```bash
owb daemon-status     # 应该看到 mode: "relay" + relay_url
owb                   # 应该两个 ✓：daemon（relay 模式）+ 扩展已连接
owb open https://example.com --new-tab true    # 真跑一条
```

用户那边扩展弹窗应该从「配对中…」变成 **「已连接」**，拓扑图三个节点全亮。

## 中转模式下有什么不一样

配通之后，**所有命令的用法完全一样**（内部路由零改动）。但有几件事必须记住：

### ⚠️ 文件落在不同的机器上

这是最容易出错的一点——本地模式下"下载下来的文件"和"我能读到的文件"是同一个，
中转模式下**不是**：

| 命令               | 文件实际在哪                                     | 你能不能读到                 |
| ---------------- | ------------------------------------------ | ---------------------- |
| `owb download`   | **用户机器**的系统下载目录（Chrome 下载 API 只能存那儿）       | ❌ 读不到                  |
| `owb file fetch` | **daemon 机器**的 `work/downloads/`（daemon 自己发起的 HTTP 拉取） | ✅ 能读                   |
| `owb shot --out` / `owb pdf --out` | **你这边**（CLI 把数据落盘在本地）                       | ✅ 能读                   |
| `har save` / `state save` / `task` 归档 | **daemon 机器**的 `work/`                     | ✅ 能读                   |
| `owb upload`     | 不碰文件系统（base64 走页面内 DataTransfer）           | ✅ 中转模式下照常可用            |

⚠️ **`file fetch` 是 daemon 自己去拉 URL，不带用户浏览器的登录态**——需要登录
才能下的文件，它会拉回一个登录页。这类文件要么让用户自己下，要么先
`owb state save` 后在 daemon 侧另想办法。

### 延迟与超时

每条命令多走一趟公网往返。影响：

- **30 秒的 CDP 硬超时更容易撞到**（见 SKILL.md「三层超时」）。慢站优先
  `--wait-until domcontentloaded`，快照优先缩小 `--max-nodes` 而不是加大。
- 大返回（整页截图、全量快照、HAR）传输更慢——**更要用 `--since-last` 增量快照**，
  HAR 一律 `har save` 落盘而不是回显。
- 断线重连退避上限从 15 秒放宽到 **60 秒**（每次重连都是一次中转计费请求），
  所以中转模式下掉线恢复**比本地慢**，看到 `NO_EXTENSION` 多等一会儿是正常的。

### 用户就在浏览器旁边——而且他看不到你

本地模式下用户至少知道 agent 在同一台机器上跑。中转模式下你是**从别处**操作
他的浏览器的，他只看到标签页自己动。所以：

- **`--new-tab true` + `--active false` 更该带上**，别抢他的屏幕
- 做任何改变状态的操作前**说清楚**，比本地模式更需要提前打招呼
- 用完 `owb tab close-group` 清场，别把标签页留在别人机器上

## 安全边界（配之前必须让用户知道）

- **token 是线上唯一的秘密。** 拿到 token 的人 = 能完全控制这个浏览器
  （含全部登录态）。别外泄、别进仓库、别在对话里回显。
- **中转是可信 broker，当前没有端到端加密。** 中转服务能看到全部明文流量，
  **包括 cookie 和 storage**。所以**必须用用户自己的 Cloudflare 账号部署**，
  别用别人提供的公共中转。
- 传输本身走 `wss://`（Cloudflare 边缘 TLS）。token 在 URL 路径里——传输是加密的，
  但会出现在用户自己 CF 账号的请求日志里。
- 同 role 重连会顶替旧连接；任一端断开即断对端。
- **不用了就关掉**：扩展弹窗切回「本地」页保存（会清空中转字段），daemon 侧
  取消那两个环境变量并重启。

## 故障排查

| 症状                                            | 原因与处置                                                          |
| --------------------------------------------- | -------------------------------------------------------------- |
| 扩展弹窗停在**「配对中…」**                              | 只有一端到位。**正常状态**，等另一端接入；两端都配了还这样 → 检查 token 是否完全一致（掩码对一下头尾）     |
| 扩展弹窗**「未连接」**，提示检查 URL 与 Token                | 中转 URL 写错或没部署成功；`curl https://<relay>/health` 验一下              |
| `owb daemon-status` 仍是 `mode: "local"`         | 两个环境变量没齐，或**旧 daemon 还活着**。停掉它再重跑（daemon 只在启动时读环境变量）           |
| 一直 `NO_EXTENSION`，退避重试也不好                     | 用户机的扩展没连上中转。让用户看扩展弹窗状态；中转模式重连退避上限 60 秒，比本地慢                    |
| `Exceeded allowed volume of requests in Durable Objects free tier` | Cloudflare 免费额度（每月 1M DO 请求）耗尽，每月 1 号重置；或升级 Workers Paid（$5/月） |
| `error code: 1042` 或 404（没进 worker）            | workers.dev 路由没启用，确认 `wrangler.toml` 里 `workers_dev = true` 后重新 deploy |
| 裸 `1101` 且没有任何信息                              | 异常在 catch 层之外（部署损坏/平台故障）。`npx wrangler tail` 看堆栈；换 worker 名重部署  |

更细的中转服务本身的部署、测试、配额说明在仓库 `owb-relay/README.md`。
